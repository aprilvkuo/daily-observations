# 来源与解读

## 先确定能读到什么

输入可以是 arXiv URL/编号、其他论文官网、PDF、已有解读或当前聊天。沿用用户明确的论文版本；链接未锁定版本时查官方版本记录，记录实际阅读的版本。原论文发布日期与本站解读日期分开。

阅读原文的方法、实验、局限及与用户问题相关的附录。网页或搜索工具无法读完整 PDF 时，尝试官方 HTML、PDF 阅读工具或用户已上传的全文；仍不可得时交付标注范围的阅读提纲/局部分析，指出缺少的材料。不要因拿到了摘要就声称已核验全部实验。

从官方论文页面/PDF核对标题、作者、首次发表日、版本、摘要和链接。官方代码需要论文、作者主页或已验证项目之间的明确关联；无代码链接可以省略，不按实验室名称猜 GitHub 地址。非 arXiv 论文不必有 arxiv_id。元数据未知字段省略，正文可说明待核验。

## 文章的内容

开头给出核心问题和主要判断。后文按内容需要展开：

1. 研究问题与已有方法的缺口。
2. 方法如何工作，关键假设、公式或算法步骤。
3. 实验设置：数据、模型、基线、指标、计算条件与具体表/图。
4. 结果支持什么、尚未支持什么；局限和失败案例。
5. 对用户关心的研究或工程的启发，以及需要验证的假设。
6. 原论文、官方代码及实际使用的补充来源。

不用为每篇强行凑齐相同章节，不把论文的宣传句当验证结论。每个数字保留任务、指标和基线；没有来源就不补数值。明确区分论文报告、我们的推断和用户自己的观点。长公式说明符号，示例代码标注示意或实际运行及其条件。未做实验就不写“复现成功”。

已有聊天里的研究讨论是素材，不能直接当证据。保留其问题、异议和用户的推理；补查引用，修正事实错误，必要时说明哪些判断尚待验证。不要把聊天中无关个人信息带入公开稿件。

## 阅读格式

标题使用 `##`/`###`，自动目录由生成器产生，不手写容易失效的目录锚点。支持 `$...$`、`$$...$$`、`\(...\)`、`\[...\]`；代码用带语言的围栏，流程图用 `mermaid` 围栏。源码中的 JSON 反斜杠必须经序列化保留。

图片仅使用实际可访问的来源，标明原图/改绘和论文图号，不伪造实验曲线。当前生成器只复制web顶层文件，优先将有权使用的必要资源提交到 `web/<slug>-图名.svg`（或其他真实图片格式），文章使用 `../assets/<slug>-图名.svg`；不要嵌套到web子目录或提交完整PDF。远程图片需检查目标可用性，并提供说明文字。若当前工具不能处理图片文件，先用有来源的文字或Mermaid解释，不留断图。

网页正文引用使用 `[原论文 §3](https://...)` 一类标准链接；表格数据标原表号。确认页面在移动端没有全页横向溢出，长公式/代码可局部滚动。CDN失败时原站会保留公式/图表源码，预览时如发生需说明。
